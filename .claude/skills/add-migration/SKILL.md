# Thêm PostgreSQL migration

Đầu vào (`$ARGUMENTS`): `<service> <mô-tả-ngắn>` (ví dụ: `order add_cancel_actor`, `payment add_payout_note`).

Đọc quy tắc chi tiết ở `.claude/rules/migrations.md` trước khi viết SQL. **Tuyệt đối không sửa file migration đã merge.**

## 1. Xác định thư mục, cách đánh số và runner của service

Chỉ dùng migration đi tới (**forward-only**, không tạo file `down`). Kiểm tra file mới nhất trong thư mục của service rồi tăng số thứ tự lên 1:

| Service | Thư mục & mẫu tên file | Runner khi khởi động | Tầng query |
| --- | --- | --- | --- |
| `user` | `services/user/migrations/000N_<tên>.sql` | `services/user/internal/db/migrate.go` (`schema_migrations.version`, có tx) | `sqlc` |
| `order` | `services/order/migrations/000N_<tên>.sql` | `services/order/internal/db/migrate.go` (`schema_migrations.filename`, có tx) | `sqlc` |
| `payment` | `services/payment/migrations/000N_<tên>.sql` | `sqlx::migrate!("./migrations")` ở `services/payment/src/main.rs` (`_sqlx_migrations`, kiểm checksum) | SQLx runtime |
| `product` | `services/product/migrations/00000N_<tên>.sql` | `services/product/migrations/embed.go` (`schema_migrations.filename`, có tx) | `sqlc` |
| `notification` | `services/notification/migrations/00000N_<tên>.sql` | `services/notification/internal/db/migrate.go` (**chạy lại mọi file**, không có `schema_migrations`) | `sqlc` |
| `shipping` | `services/shipping/migrations/00000N_<tên>.sql` | `MigrateAndSeed` ở `services/shipping/internal/store/store.go` (**chạy lại mọi file**, không có `schema_migrations`) | pgx viết tay |
| `promotion` | `services/promotion/internal/store/migrations/00N_<tên>.sql` | `Migrate` ở `services/promotion/internal/store/store.go` (**chạy lại mọi file**, không có `schema_migrations`) | pgx viết tay |

`cart` chỉ dùng Redis, không có PostgreSQL migration.

## 2. Viết file migration mới

- [ ] Chỉ đụng DB của chính service đó (`<service>_db`); không tạo bảng hay khóa ngoại chéo DB.
- [ ] **Tương thích ngược (expand-and-contract)**:
  - Thêm cột mới phải cho phép `NULL` hoặc có `DEFAULT` hằng số để bản binary cũ không vỡ khi rolling update.
  - Không `DROP COLUMN` / đổi tên cột đang có code đọc-ghi trong cùng một đợt; tách thành 2 bước (ngừng đọc-ghi trước, xóa sau).
- [ ] **Kiểu dữ liệu và đặt tên**:
  - Tiền tệ: `BIGINT` (`*_vnd`), kèm `CHECK (... >= 0)` hoặc `> 0`; cấm `FLOAT`, `DOUBLE PRECISION`, `NUMERIC` cho tiền VND.
  - Thời điểm: `TIMESTAMPTZ` (UTC).
  - Định danh người bán: `shop_id` (không dùng `seller_id`).
- [ ] **Index**: thêm `CREATE INDEX` cho các cột lọc, khóa ngoại, hoặc sắp xếp mới; ưu tiên partial index cho hàng đợi/trạng thái pending (mẫu `idx_outbox_events_unpublished` trong `services/order/migrations/0001_init.sql`).
- [ ] **Idempotent bắt buộc cho `notification`, `shipping`, `promotion`**: vì runner của 3 service này chạy lại toàn bộ file `.sql` mỗi lần khởi động, mọi câu lệnh trong đó phải dùng `IF NOT EXISTS` (`CREATE TABLE IF NOT EXISTS`, `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`).
- [ ] Không sửa file migration cũ đã merge: trên DB đang có, runner `schema_migrations` sẽ bỏ qua, còn `payment` (`sqlx::migrate!`) sẽ crash vì lệch checksum.

## 3. Cập nhật query và tầng store

- [ ] **Service dùng `sqlc`** (`user`, `product`, `order`, `notification`):
  - Cập nhật SQL trong `services/<svc>/queries/*.sql` (và `rename`/`overrides` trong `services/<svc>/sqlc.yaml` nếu cần).
  - Chạy `cd services/<svc> && sqlc generate`.
  - Không sửa tay các file sinh trong `internal/db/` (có dòng `Code generated by sqlc. DO NOT EDIT.`; chỉ `internal/db/migrate.go` là code viết tay).
- [ ] **`payment` (Rust)**: repo không dùng macro `sqlx::query!` compile-time; cập nhật trực tiếp các truy vấn `sqlx::query` / `sqlx::query_as` / `sqlx::query_scalar` và struct `sqlx::FromRow` trong `services/payment/src/` (`src/service.rs`, `src/ledger.rs`, `src/workers.rs`).
- [ ] **`promotion` và `shipping`**: cập nhật câu SQL pgx viết tay trong `services/<svc>/internal/store/store.go` (và `memory_store.go` nếu có).

## 4. Test

- [ ] Cập nhật hoặc thêm unit test ở tầng store/service phản ánh schema mới (lưu ý kiểm tra cả `memory_store.go` / stub repo trong test nếu thay đổi interface `Repository`/`Store`).
- [ ] Kiểm tra migration áp dụng được sạch từ đầu và (với `notification`/`shipping`/`promotion`) chạy lặp lại lần 2 không lỗi.
