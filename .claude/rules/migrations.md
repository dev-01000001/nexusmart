# Quy tắc Migration cơ sở dữ liệu

- **Forward-only theo hiện trạng repo**: repo chỉ chạy migration một chiều đi tới, không có file `.down.sql` hay cơ chế rollback (dù brief gốc có nhắc cặp up/down; muốn đổi sang mô hình up/down cần ADR được duyệt).
- **Không sửa file đã merge**: mọi thay đổi schema phải tạo file migration mới.
  - `order` (`services/order/internal/db/migrate.go`), `product` (`services/product/migrations/embed.go`) ghi tên file vào `schema_migrations(filename)` và `user` (`services/user/internal/db/migrate.go`) ghi vào `schema_migrations(version)` — sửa file cũ sẽ bị bỏ qua trên DB đã tồn tại.
  - `payment` dùng `sqlx::migrate!("./migrations")` (`services/payment/src/main.rs`) kiểm checksum — sửa file cũ làm service lỗi khi khởi động.
  - Lưu ý hiện trạng: `promotion` (`services/promotion/internal/store/store.go`), `shipping` (`services/shipping/internal/store/store.go`) và `notification` (`services/notification/internal/db/migrate.go`) chưa dùng bảng `schema_migrations` mà chạy lại toàn bộ `.sql` mỗi lần khởi động — mọi DDL trong 3 service này bắt buộc phải idempotent (`IF NOT EXISTS`, v.v.).
- **Đánh số theo quy ước sẵn của từng service**:
  - `0001_`: `user`, `order`, `payment`.
  - `000001_`: `product`, `shipping`, `notification`.
  - `001_`: `promotion` (`services/promotion/internal/store/migrations/`).
- **Tương thích ngược (expand → migrate → contract)**: tách thay đổi phá vỡ qua nhiều bản phát hành. Cột mới phải cho phép `NULL` hoặc có `DEFAULT`; không `RENAME`/`DROP` hay đổi kiểu cột đang được code cũ đọc/ghi trong cùng một bản.
- **Index và `CREATE INDEX CONCURRENTLY`**: bổ sung index cho khoá ngoại và cột lọc chính (`shop_id`, `user_id`, `order_id`, `status`...). Không đặt `CREATE INDEX CONCURRENTLY` trong file migration thông thường vì runner của `order`/`user`/`product` bọc mỗi file trong `pool.Begin` transaction (`services/order/internal/db/migrate.go`), `sqlx::migrate!` mặc định chạy trong transaction, và `pool.Exec` multi-statement chạy trong implicit transaction nên PostgreSQL sẽ báo lỗi. Bảng lớn cần tạo index không khoá phải dùng bước DDL riêng ngoài transaction.
- **Đồng bộ `sqlc`**: sau khi sửa schema hoặc query ở 4 service dùng `sqlc` (`user`, `product`, `order`, `notification` — có `sqlc.yaml`), chạy `cd services/<svc> && sqlc generate`. Không sửa tay file có dòng `Code generated by sqlc. DO NOT EDIT.` trong `internal/db/` (`internal/db/migrate.go` là file viết tay).
